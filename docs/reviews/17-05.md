# Deep Review — LangGraph Orchestration Architecture

**Fecha:** 2026-05-17
**Scope:** Arquitectura de orquestación LangGraph para el pipeline de scan (barcode → Open Food Facts → Gemini → ChromaDB → PostgreSQL)
**Método:** Panel adversarial (devil's-advocate ↔ steelman × 2 rondas + red-team + risk-analysis + pre-mortem)

---

## Veredicto

- **A favor:** LangGraph checkpointing hace el pipeline auditable y reanudable — correctness requirement para health data, no nice-to-have. TypedDict isolation por invocación es arquitectónicamente correcto.
- **En contra:** Retry cost amplification es estructural (replay re-ejecuta subgraph completo, multiplica tokens bajo degradación). La propuesta llega a producción con 3 brechas críticas de seguridad no resueltas.
- **Juicio:** LangGraph es la arquitectura correcta — no cambiarla. La configuración actual no es shippable. Los 3 criticals de abajo deben resolverse antes de cualquier deploy con usuarios reales.

---

## Hallazgos críticos (bloquean launch)

| # | Hallazgo | Ubicación | Mitigation |
|---|---|---|---|
| 1 | **PostgreSQL checkpointer serializa TypedDict a blob sin AES-256** — bypassa la encryption policy del proyecto | `PostgresSaver`, config del checkpointer | Subclasear `PostgresSaver`, interceptar `put()`/`get()` con `Fernet.encrypt(json.dumps(state).encode())` usando la misma AES-256 key del stack |
| 2 | **ChromaDB sin tenant isolation** — `top_k=10` puede cruzar resultados entre usuarios | `collection.query()`, cualquier llamada sin filter | Agregar `where={"user_id": current_user.id}` en cada query; si la collection es shared, migrar a `collection-per-user` y forzar el metadato en `add()` |
| 3 | **Prompt injection via Open Food Facts** — ingredientes son editables públicamente, llegan directo a Gemini sin sanitización | Transición step 2→3, template del prompt nutricional | Allowlist `[a-zA-Z0-9,().%\s-]` en `ingredients_text` antes de interpolar; hardcodear system-role prefix no interpolable desde input |

---

## Riesgos priorizados

| Riesgo | Prob | Impacto | Mitigation |
|--------|------|---------|-----------|
| **PostgreSQL checkpoint sin AES-256** | Alta | Alto | Subclasear `PostgresSaver` — `put()` cifra, `get()` descifra, falla-loud si falla |
| **ChromaDB sin tenant isolation** | Alta | Alto | `where={"user_id": ...}` en cada `collection.query()` |
| **Prompt injection via Open Food Facts** | Alta | Alto | Allowlist + system-role prefix hardcodeado |
| **Sin backpressure en FastAPI → OOM bajo retry storms** | Alta | Alto | `asyncio.Semaphore(max_concurrent=50)` + HTTP 429 con `Retry-After: 2` |
| **LangSmith tracing envía health data a vendor externo** | Media | Alto | `LANGCHAIN_TRACING_V2=false` en prod hoy; RunProcessor custom que redacte `state["nutrients"]` y `state["biomarkers"]` si tracing es necesario |
| **Retry no idempotente en checkpoint writes → análisis duplicados** | Media | Alto | `INSERT ... ON CONFLICT (thread_id, checkpoint_id) DO UPDATE SET ...`; `checkpoint_id` = hash del estado + step, no UUID |

---

## Failure modes adicionales (pre-mortem)

- **Open Food Facts sin circuit breaker** — cuando la API externa cae, todo el servicio cae con ella. Agregar timeout explícito + fallback (cache o error 503 con retry-after al cliente).
- **TypedDict schema evolution silenciosa** — un refactor que renombra una key en step N rompe step N+1 sin error visible. Agregar validación Pydantic del TypedDict entre nodes o un test de contrato por cada transición de step.

---

## Argumentos del debate que sobrevivieron

| Punto | Resultado |
|---|---|
| TypedDict race conditions | **steelman ganó** — cada `graph.ainvoke()` crea estado aislado por invocación |
| Checkpoint serial writes (1,000/sec) | **empate** — concern real, solucionable con asyncpg pool config |
| Retry cost amplification | **devil's ganó** — riesgo estructural, no solucionable con config |
| Latencia serializada P99 (8-15s con retries) | **devil's ganó parcialmente** — datos de UX vs argumento filosófico |
| LangSmith compliance | **steelman ganó parcialmente** — LangGraph separable de LangSmith; DEFAULT es el riesgo |

---

## Acciones requeridas

- [ ] Subclasear `PostgresSaver` para AES-256 en checkpoint writes/reads
- [ ] Agregar `where={"user_id": ...}` en todos los `collection.query()` en `rag.py`/`retrieval.py`
- [ ] Sanitizar `ingredients_text` antes de interpolar al prompt de Gemini
- [ ] `asyncio.Semaphore(50)` + HTTP 429 en `/scan/barcode`
- [ ] `LANGCHAIN_TRACING_V2=false` en `.env.prod`
- [ ] `INSERT ... ON CONFLICT` en checkpoint writes — `checkpoint_id` determinístico
- [ ] Circuit breaker para Open Food Facts API
- [ ] Validación Pydantic o test de contrato en transiciones de step del graph
